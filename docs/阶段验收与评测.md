# 阶段验收与评测

版本：0.2 草案。日期：2026-10-20。以下是未来验收计划，**本轮没有运行任何测试**。阶段通过须附实际证据，不能由文档完整推断实现完成。

## 1 阶段和准入

| 阶段 | 准入条件 | 交付物 | 通过条件 |
|---|---|---|---|
| S0 设计冻结与接入核查 | 用户确认简化架构；当前正在文档阶段 | 契约、宿主版本与公开接口证据、存储决策、量化阈值 | 唯一状态源、启动门禁、验收角色、恢复和旁路边界明确；核心待决项有决策，不把 DS 转述冒充独立验收 |
| S1 核心与离线模拟 | S0 通过，用户另行启动实现 | 规范化、诊断、启发式、执行段、调配器状态机、模拟执行器和持久化 | 合成场景满足硬约束，重复/乱序/恢复有正确结果；算法与宿主解耦 |
| S2 可视化与离线闭环 | S1 通过，已有带版本模拟状态 | 任务图、详情、视图同步和操作回写 | 浏览器可读，图与快照一致；预测/实际、交付/验收、停止请求/确认分明 |
| S3 Harness 隔离接入 | S1、S2 通过；实验隔离方案获准 | agent-team 适配、工具包装、自建面板、版本与目录记录 | 无模型部分先验收；实际写入范围、合法 caller、故障行为和包解析确认；不存在原生板解锁路径 |
| S4 小规模真实协作 | S3 可验收部分通过；模型、预算、测试项目和权限获明确授权 | 持久专项对话、开发测试闭环、运行与费用记录 | 实际并发、交付、验收、冷恢复与消息控制验证；效率结果按真实数据报告 |
| S5 交付与可迁移性 | S4 通过且用户决定分发范围 | 安装说明、支持版本、回退方案、评测报告、兼容接口说明 | 约定范围回归通过；安装卸载不破坏用户数据；其他平台只按已验能力标注支持 |

S3 若某项必须调用模型，则标“待 S4 实测”，不得将 S3 的静态或模拟证据作为运行通过。首版不要求发布远程仓库、不要求第二平台可运行；第二平台可通过后续适配验证。

## 2 S0 必须冻结的设计参数

- 输入 schema、任务及 attempt 状态、验收与授权角色。
- 存储后端、提交边界、单写者方式、损坏和迁移策略。
- 计分规则、unknown 处理、稳定平局规则和随机种子策略。
- 最大成员数、执行段任务数／时长／上下文预算，消息大小与速率。
- 基准图规模、图刷新延迟、规划耗时和恢复时间目标。
- 目标 Harness 包版本、实际解析路径、工具暴露清单、UI 接入方式。

这些参数目前未冻结。评审应填入具体数值或明确“不作为当前阶段承诺”，不能在跑完实验后修改阈值迎合结果。

## 3 合成场景及判定

| 编号 | 场景 | 核心判定 |
|---|---|---|
| V01 | 串行链 | 合并委托可减少次数，但每个任务仍逐项取得许可 |
| V02 | 分叉汇合 | 无冲突分支可并行；汇合等待所有指定输入验收 |
| V03 | 跨类别反复依赖 | 执行段止于真实外部阻断，后续验收后重算 |
| V04 | 共享文件读写冲突 | read/read 可并存，涉及 write 按规则互斥 |
| V05 | 授权缺失、撤销、过期 | 不发新许可；活动任务走协调，不假称已停止 |
| V06 | 交付未验收、验收拒绝 | 下游不启动；失败和修复有独立 attempt 与历史 |
| V07 | 中间产物提前交付 | 指定下游及时解锁，上游无需结束整段 |
| V08 | 循环、缺失引用、未知耗时 | 诊断可定位；不漏掉坏图，不把 unknown 当零 |
| V09 | mock 与接口约定 | 准备用例可使用 mock；真实联调仍要求真实输入 |
| V10 | 动态新增任务、资源或输入改变 | 重算范围包含共享竞争者；失效结果可追溯 |
| V11 | 重复、迟到、乱序和丢失确认 | 不重复启动；无法判定时 unknown，不盲目重发 |
| V12 | 崩溃、失联和恢复 | 已提交状态保留；确认停止前不释放冲突资源 |
| V13 | 第二调度者接管 | 旧 epoch 写入拒绝；新调度者不自动取得宿主 Lead 权限 |
| V14 | 人工介入专项对话 | 影响范围登记并复核；普通消息不自动验收 |
| V15 | 图通知丢失与重连 | 核心不回退；刷新恢复正确 revision |
| V16 | 多任务相同文本、重复错误洪泛 | 业务 ID 去重不误删；故障有界合并且不静音 |

未来执行时，每例记录输入图、策略、事件序列、预期、实际、版本和证据位置；失败和 unknown 同样保留。图中状态对照源快照，而不是截图看起来合理就判通过。

增量重算与全量参考使用同一冻结策略、已运行任务和决策规则；核对可行性、受影响任务分数和遗漏。若局部算法允许不同的等价排序，应事先规定等价条件。

## 4 公平对照

基线为逐原子任务派发、按类别整包、仅拓扑顺序调度。所有基线使用同一任务图、估计、资源、执行者容量、验收延迟、授权事件、故障序列和预算。

类别整包遇到外部依赖时必须停下并等待／恢复，不能跳过门禁；无法完成时记录阻塞或超时，不删除该样本。仅拓扑基线仍执行必要的资源和权限检查，不能通过违反约束换取速度。

固定输入集、种子、策略版本、模拟时钟规则和参数调优集。验收数据与调参数据区分；比较时计入交接、验收、调度及人工激活延迟。

消融比较至少包括关闭执行段融合、关闭上下文连续性偏好、关闭下游解锁价值。不能通过扩大单包、延迟中间交付、遗漏失败或缩减验收来制造提升。

## 5 指标口径

| 指标 | 口径与限制 |
|---|---|
| 总完成时间 | 项目起点至全部必需输出有效验收；未完成样本记录超时或未完成，不伪造终点 |
| 阻塞时间 | 每个执行者因依赖、资源、授权或验收等待的累计时长，按原因分类避免同一时段重复计数 |
| 空闲时间 | 可用容量内无活动任务且无已归属阻塞工作的时长；未激活会话另列 |
| 派发／交接次数 | 区分业务委托、传输重试、执行者切换和人工转交；不只统计最终成功记录 |
| 有效推进量 | 对预先固定权重的有效验收节点／产物计数；重复尝试不重复加分，失效产物另记 |
| 返工量 | 因缺陷、输入失效或错误协调而重复的工作时长／任务量；原因未知保留 unknown |
| 约束违规 | 未验收启动、越权启动、冲突资源并发许可等逐项计数；任何确认的硬违规阻止验收通过 |
| 调度介入 | 人类和调度对话的决定、转述、恢复操作分别计数 |
| 上下文开销 | Lead 与各执行者输入量、摘要量、重复背景量分别记录，避免只把开销挪走就算节省 |
| 压缩次数 | 有可靠宿主事件才实测；否则仅报告上下文长度等代理指标及局限 |
| 请求与费用 | 按实际请求和 usage 汇总；回合数不等于请求数，缺失用量不计为零 |

模拟耗时不能当作真实开发工期，模拟上下文估计不能证明实际压缩减少。多次真实试验需报告波动和失败样本，不承诺预设百分比提升。结果可以是不改善；只要方法可信就如实记录并调整策略。

## 6 Harness 验收边界

- 本轮不运行配置导出命令。后续先核实命令、输出敏感性、解析版本及启动副作用。
- 新 profile 不等于独立数据环境；会话、storage、附件、设置、缓存、凭据与全局 patch 的写入位置都需说明。
- 不以真实旧会话或当前开发目录作为默认试验对象，不并发启动未经确认的共享状态实例。
- 验证持久专项会话、恢复及上下文回传量，不仅验证能创建 teammate。
- 核对原生任务写工具未暴露，核心任务查询和启动许可全程有效；明确其他插件或任意 shell 的旁路边界。
- UI 图展示、成员会话跳转、消息回传和业务验收分别检查；宿主结束不是任务通过。
- 真实试验先固定模型、请求与预算上限、停止条件及允许工具，不用未经测量的“几分钱”代替预算。

## 7 检查频率与交付证据

实现后按模块完成进行针对性测试，子系统完成后验证衔接，最终交付时按约定范围回归。已有同版本同条件有效结果可复用；不对每个小改动机械重跑全部检查。

证据分层：文档评审／源码核查／离线模拟／持久化测试／浏览器检查／宿主接入／真实模型。每层记录通过、失败、未测试或 unknown。跨批次结果保留批次和环境，不汇总成一次不存在的干净运行。

本轮只交文档并回读内容；上述场景、性能、宿主和模型验证全部 **未测试**。
