# Harness 接入证据

日期：2026-10-20。版本：0.2。证据包含此前本会话的本地静态核查和随后用户提供的 DS 调查报告。本次仅整理文档，没有重新检查宿主、启动命令、发送消息、创建测试会话或调用模型。

## 1 决策

用户确认采用 **复用 agent-team 成员生命周期和通信，自建唯一权威调度状态** 的简化方案。原生任务板、闸门任务和双写镜像不进入首版；headless 降为后续备选。

子会话归属关系与模型上下文回传量分别判断。若报告中的行为成立，teammate 的完整轨迹留在自身会话，Lead 主要接收主动消息与查询结果；插件仍需控制摘要量，不能承诺调度对话不增长。

## 1.3 当前接入待办

1. 固定宿主与插件包版本，核查安装作用域和旧 junction 的解析优先级；不能由目录存在或 desktop 正常运行推断。
2. 证明公开服务可在合法 live Agent 上下文中调用，不以 internal 接口为默认依赖。
3. 不加载原生任务写工具，确定成员、查询、中断、消息包装工具的发现与身份规则。
4. 明确核心存储单写者、持久化提交、恢复和迁移机制；`ctx.storage` 是否满足要求待评估。
5. 选择自建视图的数据传输方式，证明展示滞后可恢复且不会影响执行门禁。
6. 制定独立实验环境方案。覆盖 sessions/storages 两个目录不等于完全隔离；附件、设置、缓存、凭据和全局 patch 仍须列入写入清单。
7. 配置导出类命令的存在性、启动副作用和敏感字段都未核实；本轮不执行 `--dump-config` 等命令。

原生任务板镜像、Lead 专属 gate 任务、描述字段内嵌状态 JSON 都不是首版前置。人类直接干预是正常产品入口，不要求将用户全部消息回传 Lead。

| `dsh-session-persistence-jsonl/lib/index.js:617-685` | 持久化写句柄持有跨进程写入所有权；Windows 使用命名内核信号量，冲突映射为 SessionAlreadyOwnedError |

`withFileLock` 在其他包中存在，并不能证明 headless 会话竞争会自动排队。当前打包版上述路径表明占用会报错，因此队列应由调配器负责。

“一次工作回合”也不等于“一次模型请求”：runner 等待 agent 工作停稳，期间可能有工具循环、重试及子任务。模型调用数和费用需要独立计量。

## 4 headless 后续备选验证

1. 实际 CLI/profile 加载的是哪个包版本、使用哪个 DSH_HOME，以及配置覆盖顺序。
2. 在隔离测试环境中创建独立会话，可靠获取 ID，续跑后确认上下文保留与持久化。
3. `--json` 的事件字段、会话 ID、运行标识、终止原因、usage 和截断／错误行为；不得凭字段名称猜测协议。
4. GUI 关闭页面、释放 Agent 或退出应用分别会否释放写入所有权；重新打开能否看到 headless 交付。
5. 两个不同会话能否安全并行；共享工作区索引、查询缓存等状态是否仍有竞争。
6. 同一会话占用、超时、崩溃与结果未知时的恢复；不能因超时盲目重发。
7. headless 的模型、工具、工作目录和权限配置与目标会话预期是否一致。
8. 专项对话无需 preset 的职责约定是否足够；需要 preset 的会话如何通过公开接口支持，而不是绕过接管检查。
9. 独立测试 home/profile 能否在不接触真实会话的前提下使用；默认不并发启动共享真实 home 的 GUI 与 headless。

## 5 验证授权边界

后续先进行源码和离线协议验证。需要真实模型的步骤必须明确模型、费用上限、回合与请求计量、测试目录和清理范围后获得授权。

转述中的“要不要实测”“给我两个 session ID”是另一段回复，不构成本项目的测试投递授权。已有真实会话不作为默认试验对象。测试记录先保留；删除测试会话须另行确认，不自动清理。
