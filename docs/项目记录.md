## 2026年10月20日 设计草案更新

用户确认名称为 Multi-Agent Dynamic Task Scheduler，面向开发和测试，DeepSeek Harness 插件优先，核心兼容其他平台。目标是以 1—2 个调度对话协调多个专项对话，减少上下文压缩、转述与交接，提高有效并行推进量。

早期文档采用 headless 续跑候选方案；随后用户提供 DS 的 agent-team 调查报告，并确认简化方向。本次恢复的是文档工作，授权明确不包含实现代码、DSH 配置修改或测试运行。

### 当前决策

1. 复用 agent-team 成员生命周期和消息通道，保留独立持久上下文。
2. 自建唯一权威 ScheduleStore；不使用原生任务板调度，不维护双板镜像，不设置原生 gate。
3. 门禁位于每个原子任务的认领／启动路径；交付与验收分离。
4. 可视化从核心事实派生；展示同步失败不回滚事实。
5. 人类直接介入是正常入口；影响任务的变更登记，普通聊天不自动验收或扩权。
6. 资源锁是协作协议，不冒充文件系统安全隔离；失联不自动释放资源。
7. 宿主投递缺乏幂等时，不承诺恰好执行一次；unknown 进入对账。
8. headless 和其他平台保持备选，不阻塞首版；不涉及 AIC 实施。
