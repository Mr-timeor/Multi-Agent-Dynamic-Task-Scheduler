## 生成独立目录

```powershell
npm run package:local
$release = Get-Content -Raw .scheduler/releases/latest.json | ConvertFrom-Json
$packageRoot = $release.directory
Get-Content -Raw (Join-Path $packageRoot 'manifest.json')
```

每次创建新的`.scheduler/releases/scheduler-0.1.0-*`目录，不覆盖旧包。构建器直接编译到该目录；不运行原来的build/build:view，不更新两个已安装插件的源码或dist，不修改DSH配置。

目录内包含可单独运行的`core/dist`、两个可安装的`harness`包、开发示例、七组合成评测及接入说明。核心没有运行时npm依赖；插件peer依赖由DSH宿主提供。没有复制node_modules、宿主包、真实任务状态、试用产物、会话或凭据。manifest记录版本、构建时间和文件列表；不是代码签名或兼容性证明。

在分发目录中可直接运行，无需npm install：

```powershell
Set-Location $packageRoot
node core/dist/cli.js plan fixtures/development.json
node core/dist/cli.js graph fixtures/development.json flow.html
node core/dist/benchmark/run.js fixtures/benchmarks
```

分发目录可复制到别处使用。插件配置中的projectFile、stateFile、graphFile仍需使用目标机器的实际路径；旧项目状态不会随插件一起迁移。manifest写入前的目录属于未完成构建，不用于接入。

## 给肥鱼：验证分发产物

工作目录仍是源码仓库。读取`.scheduler/releases/latest.json`取得本轮包路径，并把该路径记入验证结果；验证中不再重打包，避免验到另一份产物。先读取`manifest.json`，确认目录内两个插件入口和dist存在。

以下命令只准备和运行隔离home，使用本轮分发包，不修改真实desktop profile。现有宿主路径默认是`D:\deepseek-harness\desktop\DeepSeek Harness.exe`；实际位置变化时设置DSH_DESKTOP_EXE。探针依赖本机0.2.1-rc.2的app.asar路径，版本或路径变化时先调整接入测试，不据旧结果宣称新宿主兼容。

```powershell
$release = Get-Content -Raw .scheduler/releases/latest.json | ConvertFrom-Json
$packageRoot = $release.directory
$env:SCHEDULER_BUNDLE_DIR = Join-Path $packageRoot 'harness/bundle'
$env:SCHEDULER_VIEW_BUNDLE_DIR = Join-Path $packageRoot 'harness/view-bundle'
try {
  # 基础加载：四工具、身份隔离、释放清理
  node tests/host/setup-isolated.mjs
  if ($LASTEXITCODE -ne 0) { throw '准备隔离profile失败' }
  powershell -NoProfile -ExecutionPolicy Bypass -File tests/host/run-isolated.ps1
  if ($LASTEXITCODE -ne 0) { throw '基础宿主验证失败' }

  # 重新准备，闭环只访问本地mock，不请求真实模型
  node tests/host/setup-isolated.mjs
  if ($LASTEXITCODE -ne 0) { throw '准备mock profile失败' }
  powershell -NoProfile -ExecutionPolicy Bypass -File tests/host/run-isolated.ps1 -Loop
  if ($LASTEXITCODE -ne 0) { throw 'mock闭环验证失败' }

  # 可选图：真实宿主加载、revision跟随、只读及关闭清理
  powershell -NoProfile -ExecutionPolicy Bypass -File tests/view-host.ps1
  if ($LASTEXITCODE -ne 0) { throw '只读图宿主验证失败' }
} finally {
  Remove-Item Env:SCHEDULER_BUNDLE_DIR -ErrorAction SilentlyContinue
  Remove-Item Env:SCHEDULER_VIEW_BUNDLE_DIR -ErrorAction SilentlyContinue
}
```

这里特意不用npm run test:host、test:host:loop、test:view:host：它们会先构建仓库中的插件，可能触发junction安装副本更新。接入负责人保留命令输出及新生成报告；失败时记录发生层级和原因，重复同一失败而没有新信息时停止，不循环重试。

本轮不要求替换当前真实profile的junction安装，不重复已有GUI、真实模型或重启验收。验证分发副本后，后续是否迁移实际安装再按使用需要决定。回退本次隔离验证只需结束探针进程，原真实profile保持原样；保留失败报告。
