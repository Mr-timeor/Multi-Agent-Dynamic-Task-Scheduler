# 实施方案

2026-10-24同步当前状态。首版与020自动派发已验收，采用最小约束：普通任务直接提交，少量检查点显式验收，内部记录不要求模型手工维护。

## 已落地

- `src/core/`：类型、输入默认值、DAG诊断、资源匹配与执行段。
- `src/store/`：单进程写队列、JSON替换与上一版备份。
- `src/dispatcher/`：派发、回执、结果、验收、重试和追加任务。
- `src/ui/`：独立HTML/SVG快照。
- `harness/`：宿主ESM入口与4工具适配；不使用原生任务板。
- `fixtures/`、`tests/`：开发测试样例与离线验证。

Node.js 22+，TypeScript构建；无核心运行时依赖。当前本机Node 26.3.1验证通过，其他Node版本未实跑。宿主自己的包在安装时解析，不复制进核心。

## 算法

按硬前置诊断图；从已接受结果计算ready。以priority、可解锁后代数量、稳定ID排序，依执行者声明顺序贪心安排互不冲突的首项。owner和categories决定适配，不做额外上下文评分。

从首项沿同执行者能承担、直接依赖上一项的后继延伸，以虚拟完成推演段内条件，默认最多4项。外部前置、review和段长形成停止边界。预测只生成建议；每次next仍检查真实条件。具体排序与边界见[调度算法](调度算法.md)。

当前实现追求可解释与短闭环，不承诺最优分配。多个通用执行者的排序可能影响利用率，先通过同条件基线评估再调整。
