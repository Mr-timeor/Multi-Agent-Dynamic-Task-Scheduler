# 使用与接入

## 输入例子

`fixtures/development.json` 可直接修改后用于规划。顶层为name、agents、tasks；任务只填id也能规划，实际协作建议补title、category、dependsOn和resources。

资源使用项目相对路径。目录包含子路径，读读可并行，存在写入则互斥；构建输出和公共配置也应声明。未声明的真实文件操作无法被插件拦截。

输入中的review默认false，普通任务自报完成即可；设为true才需要Lead检查。approval是启动授权，和结果验收分开。没有默认每任务人类审批。

## 程序调用

构建后可直接引用核心模块，传输层可以是Harness，也可以是其他平台：

```js
import { readFile } from 'node:fs/promises';
import { normalize, initial } from './dist/core/model.js';
import { FileStore } from './dist/store/file-store.js';
import { Scheduler } from './dist/dispatcher/scheduler.js';

const project = normalize(JSON.parse(await readFile('fixtures/development.json', 'utf8')));
const store = await FileStore.open('.scheduler/state.json', initial(project));
const scheduler = new Scheduler(store);
console.log(scheduler.plan());
// 真实使用时，send负责向被指定的执行者传递delivery。
// await scheduler.dispatch('developer', send);
await store.close();
```

程序状态以state.json为准；打开既有文件不重新导入任务定义。新增任务使用addTasks，不能通过改输入文件悄悄替换正在执行的任务。

## Harness 接入

入口是 [harness/bundle/index.mjs](../harness/bundle/index.mjs)；`harness/plugin.mjs` 只做兼容转发。`npm run build` 会把核心 `dist` 复制到 `harness/bundle/dist`，安装前必须先构建。

插件以本地 bundle 安装进 profile（`package.json` 声明 `dsh.bundle.patch`）。入口必须作为 profile 包存在；把 patch 的 `name` 写成 profile 外的绝对 `file://` 路径会找不到宿主提供的 `@deepseek-ai/schemastery`。已用普通目录和 junction 两种安装形态验证。宿主包由安装提供，不在本项目打包。

配置字段：

| 字段 | 用途 |
|---|---|
| leadSessionId | 唯一调度 Lead 的 session ID；默认 `auto`，由第一次合法工具调用绑定，也可显式填写。绑定在进程内保持，换 Lead 需重启 Desktop |
| projectFile | 任务定义 JSON 绝对路径，必填 |
| stateFile | 该项目状态 JSON 绝对路径，必填 |
| provider | 默认 spawn，创建 fresh 专项成员 |
| autoDispatch | 默认false；true时交付后直接给已等待成员派发，新成员首次next也可领取已就绪项。020隔离及03通过并已关闭，原项目配置恢复且重启确认false |
| receiptTimeoutMs | 默认 120000 |

4 个工具见接口文档。Lead 先 `spawn` 再 `dispatch`；成员收到委托后可带 `dispatchId` 确认，也可直接确认当前唯一委托。首个任务完成后成员可空参 `scheduler_next` 继续领取；普通任务提交即完成，`review: true` 才等待验收。派发使用 agent-team 消息，内部三 ID 随委托携带。

### 安装到 desktop profile（需确认）

这一步会修改现有 DSH profile，并需要重启 Desktop，因此默认不自动执行。已隔离验证的步骤：

1. 构建：`npm run build`。
2. 用 `plugin_manager` 的 `install_bundle` 安装 `harness/bundle`（或以本地包方式加入 `profiles/desktop/node_modules`）。不要把 `harness/bundle` 直接写到 profile 外再用绝对路径加载。
3. 在 `profiles/desktop/cordis.patch.yml` 增加 agent-team 服务和本插件配置。示例：

```yaml
- insert:
    - id: agent-team
      name: '@deepseek-ai/dsh-experimental-agent-team'
      config:
        maxMembers: 8
        maxTasks: 256
        maxMessageBytes: 65536
        disposalTimeoutMs: 5000
- id: dynamic-task-scheduler
  disabled: false
  config:
    leadSessionId: auto
    projectFile: 'D:/AAA project/codex project/Multi-Agent Dynamic Task Scheduler/fixtures/development.json'
    stateFile: 'D:/AAA project/codex project/Multi-Agent Dynamic Task Scheduler/.scheduler/host-state.json'
```

bundle 自带一条 `disabled: true` 的插入行；上面按 id 覆盖它并填配置即可。**覆盖时不要再写 `name`**：bundle 行里的 `./index.mjs` 会被解析成绝对路径，写包名会触发 `name mismatch` 并被跳过。只插入 `agent-team` 服务，不挂 `tool-agent-team`，所以不会出现原生 `team_task_*` 工具。
4. 完全退出并重启 Desktop，在新会话中确认四个工具可见；再用 Lead 依次 `spawn`、`dispatch`。

1. 恢复备份：`Copy-Item "C:\Users\唐思勉\.dsh\profiles\desktop\cordis.patch.yml.bak-before-scheduler-20261020-2338" "C:\Users\唐思勉\.dsh\profiles\desktop\cordis.patch.yml" -Force`。
