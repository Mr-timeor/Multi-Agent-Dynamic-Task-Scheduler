# 只读流程图接入

2026-10-21。图渲染、自动导出、真实 Desktop 安装与原生预览验收已完成；008 关闭。

## 最小方案

`harness/view-bundle` 只监视指定JSON状态，将核心派生图导出为一个UTF-8 HTML文件。用户在DSH现有Files／文档预览中打开它；文件变化由宿主已有预览机制重新读取。不新增端口、daemon、任务板、调度工具或第二个Lead。

该bundle独立于已安装的调度器，配置使用同一个stateFile。读取不打开FileStore，不修改运行状态；状态暂时损坏时保留上一张有效图并记录错误。关闭插件时关闭文件监听与待执行刷新。

## 构建与已验证命令

```powershell
npm test                 # 30项本地检查
npm run benchmark        # 七场景、四策略的合成比较
npm run build:view       # 只构建可选图bundle
npm run test:view:host   # 隔离真实宿主，不创建Agent或调用模型
```

`test:view:host` 的home和状态都位于仓库`.scheduler/view-host-*`。验证插件加载、首次导出、状态不变、随revision更新、两个读取结果一致、释放后停止导出。每次必须产生独立结果文件，不能只凭进程退出码当作通过。

## 交给接入负责人执行

在确认安装范围后，用宿主plugin_manager安装`harness/view-bundle`，然后在desktop patch按id启用并配置：

```yaml
- id: dynamic-task-scheduler-view
  disabled: false
  config:
    stateFile: 'D:/AAA project/codex project/Multi-Agent Dynamic Task Scheduler/.scheduler/host-state.json'
    projectFile: 'D:/AAA project/codex project/Multi-Agent Dynamic Task Scheduler/fixtures/development.json'
    graphFile: 'D:/AAA project/codex project/Multi-Agent Dynamic Task Scheduler/.scheduler/live-flow.html'
```

按id覆盖时不写name。无需再插入agent-team，也无需重打包已有`harness/bundle`。关闭时将本view行禁用或移除可选bundle；不改调度器状态。

在项目会话的Files树打开`.scheduler/live-flow.html`；若点目录被隐藏，可点击对话里的该文件本地路径链接。入口最终是带授权Session的file Resource，不使用无Session的绝对Resource地址。

文档预览的自动刷新应开启。交互预览由宿主“代码工作工具”开关控制：开启后可搜索、缩放、选择详情；关闭时仍显示静态SVG、状态和建议段。本项目不自动改变该开关。

## 原生GUI剩余验收

1. 打开导出的文件，确认阶段分层与类别归属、状态、执行者、建议段和交付点可读。
2. 用现有Lead执行pause/resume等无模型动作，确认图跟随stateFile的revision，不修改任务事实。
3. 两个文档视图读取同一文件，均更新到相同revision；关闭一个不影响另一个。
4. 检查手动刷新、交互开关和卸载导出插件后的行为。原生预览重建iframe可能重置选择和缩放，首版接受此表现。

## 已有浏览器结果与区别

独立浏览器页面已实际验证：两个页面由revision 0同步到1，搜索“接口”、选中A2和缩放宽度保持；503响应保留revision 1，显示读取失败；恢复后继续更新。截图为`.scheduler/flow-preview.jpg`。
