# worklist-02：升级一个可运行的任务清单CLI

工作目录统一为调度器项目根。仅在`.scheduler/trials/worklist-02/`工作；seed是保留的旧版起点，不在seed上开发。这里模拟已有小工程的功能迭代，不使用AIC、调度器源码或真实用户材料。

目标：用一个Lead和核心、CLI、独立测试三个专项成员完成接口发布、并行开发／测试、首轮回归、缺陷处理、最终复测与使用说明。无需安装依赖、启动服务或访问网络。

## 要交付的行为

### 核心模块

`app/src/worklist.mjs`保留named export `selectTasks(tasks, options = {})`。输入是任务数组，返回：

```js
{
  items: [/* 筛选、排序、限制数量后的任务对象 */],
  matched: 2, // 筛选后、limit之前的数量
  summary: { total: 6, todo: 2, doing: 2, done: 2 } // 全部输入，筛选前
}
```

- 每项必须是普通非null对象（非数组）；`id`是非空ASCII字母／数字／下划线／连字符组成的字符串且不可重复；`title`是非空白字符串；`status`是todo/doing/done之一；`priority`是0—3的整数。额外字段允许并在items里保留。
- 输入不是数组或任一任务不合法时抛出Error（可以是子类），给出可读原因。对所有输入先校验，不能用筛选隐藏坏数据。
- `options.status`可省略，否则只能是上述三个状态；`options.limit`可省略，否则必须是正的安全整数。options本身须是非null、非数组对象。未知options键忽略，其他无效输入抛Error。
- items先按status筛选，再按priority升序，同优先级按id的JS字符串比较顺序升序（不是本机locale排序），最后按limit截断。省略status表示全部，省略limit表示不截断。
- matched和summary口径固定如上。空数组返回空items、matched=0、全零summary。
- 不修改传入数组或任务对象；不做磁盘、网络或控制台操作。items不要求深拷贝，调用方不会再修改返回项。

### CLI

升级`app/src/cli.mjs`，调用上述核心；读取的JSON顶层就是任务数组：

```text
node src/cli.mjs <tasks.json> [--status todo|doing|done] [--limit N] [--json]
node src/cli.mjs --help
```

- 文件名在第一位，后续选项任意顺序。`--status`、`--limit`各带一个值，`--json`不带值。未知选项、重复选项、多余位置参数、缺值均错误。
- `--limit`使用十进制`[1-9][0-9]*`且转成正的安全整数；不接受正负号、小数或前导零。核心的limit是number，不受CLI字符串格式限制。
- --json输出一个可解析JSON对象，内容与核心返回一致；不得混入说明文本。正常执行exit 0、stderr为空。
- 不带--json时首行：`total=6 todo=2 doing=2 done=2 matched=2 shown=1`（按实际数字），第二行`id\tstatus\tpriority\ttitle`，后续每行对应一个items项。制表符是真实tab；title中的tab、回车、换行显示成空格，JSON模式保留原文。
- 单独--help输出包含上述用法和选项的帮助，exit 0，不读取文件。--help与其他参数混用视为错误。导入cli.mjs不自动运行main或读写文件。
- 无文件、文件不可读、JSON损坏、数据或参数无效：exit 2、stdout为空、stderr有可读错误。文件路径包含空格可用；不能改写输入文件。

固定示例data/tasks.json包含6项。全部结果顺序应为W1、W5、W2、W3、W4、W6；status=todo、limit=1时items仅W5，matched=2，summary仍为total6/todo2/doing2/done2。示例用于理解，不替代测试其他输入。

## 文件归属与领取

核心成员只改src/worklist.mjs及notes/core-fix.md；CLI成员只改src/cli.mjs、notes/cli-fix.md和最终README；测试成员只改app/tests及evidence对应目录。contract由核心P1写。package.json、data与旧版legacy.test.mjs保持原样；新增测试另建文件。

收到委托先scheduler_next确认，按taskId执行。交付使用scheduler_report写摘要与声明产物引用；完成后可next连续领取，waiting则结束本回合。Lead在依赖解除后派发唤醒，成员不空转轮询。所有普通任务无需人类逐项审批。

### P1：发布接口（核心）

读取旧模块与本卡，创建`contract.md`，写清函数、CLI调用方式、错误行为、summary/matched口径、文件归属及例子。不得改需求或实现。接口实际写好即提交completed，`contract`引用该文件，立刻解锁其他两条线；不要等D1。

### D1：实现核心（核心）

按contract升级`app/src/worklist.mjs`。可以用内联Node做少量自测，不写测试成员文件。提交completed，`core`引用模块，摘要写实际检查；实现有阻断则failed/blocked，不能假报。

### C1：实现CLI（CLI）

按contract升级`app/src/cli.mjs`，不读改核心源码，按已声明接口调用即可。核心可能还在开发，先用node --check检查自身语法并检查参数分支；help和其他真实CLI运行会导入核心，统一留到Q2，避免读到对方写入中的文件。不要求为等D1而空转。交付`cli`引用该文件，摘要区分自身检查与尚未联合检查。

### Q1：独立测试（测试）

只读本卡、contract、data和legacy测试，不读src实现。用node:test与node:assert/strict新增核心及CLI测试，CLI用子进程实际执行；覆盖排序／筛选／limit口径、非法数据、输入不变、帮助、文本／JSON输出、错误码、空格路径及输入文件不变。临时输入放系统临时目录的独立子目录，结束清理本测试自己创建的文件。无需追求固定用例数。

本项只编写测试，不能在D1/C1未完成时跑集成再报伪失败。交付`tests`引用新增测试文件；保留legacy.test.mjs。

### Q2：首轮回归与缺陷报告（测试）

等待D1/C1/Q1完成，实际执行全量app测试和JSON／文本／错误路径smoke；每条命令保存stdout、stderr与exit-code到`evidence/initial/`。报告命令、Node版本、时间、通过／失败数和缺陷复现；对每个失败判定核心、CLI、测试或环境归属，有疑问原样记录。

本任务交付的是`evidence/initial/report.md`：只要真实命令已运行且报告完整，提交completed，`initial-report`引用报告，summary必须明确写“首轮测试通过”或“首轮测试失败N项”。**completed代表报告交付，不代表功能通过**，首次失败原始输出不改写。没有缺陷写无，不制造失败。命令根本无法启动或报告无法完成则failed/blocked，停止交由Lead处理。

### D2／C2：处理实际缺陷（各自开发）

读取首轮报告，只处理归属自己的模块，不改测试或对方文件。记录缺陷原因、修改及自测到notes/core-fix.md或notes/cli-fix.md，交付core-disposition或cli-disposition。没有相关缺陷就明确写“无需修改”并说明依据，不能为制造返工而改代码。两项可并行，各查自身语法、核心可做内联检查；不在核心写入时运行CLI或全量回归，由Q3统一测。

若发现是测试预期有误，在notes说明对应需求依据，不放宽产品需求；由Q3测试成员核对后纠正。超出既定接口的需求变更交给Lead，不擅改contract。

### Q3：最终复测（测试）

等待D2/C2完成，核对修复记录并新增真实缺陷的回归用例。仅在需求依据明确时修正错误测试，在最终报告解释原因；不得靠删除失败用例让测试变绿。重新执行全量测试及同组CLI smoke，将新证据保存到`evidence/final/`，不覆盖initial。

真实全量测试exit 0、smoke符合预期且无未解决需求缺陷才completed，`final-report`引用final/report.md；否则failed/blocked，保留报告并停止。最终失败不自动新增下一轮修复、不retry Q3、不修改state解锁C3。后续由Lead报告问题后另行安排。

### C3：交付说明（CLI）

仅Q3通过后更新app/README.md：安装依赖为无、实际已验证的运行示例、核心API、错误码、初测／最终报告引用及已知限制。交付readme引用此文件。不添加未验证的效率或生产可用承诺。

## 保存命令证据

在项目根执行，以Q2全量测试为例。Q3将initial换final。CLI smoke分别使用json/text/error子目录，同样保存原始输出和实际退出码；错误路径预期exit 2不是测试框架失败。

```powershell
$appRoot = Join-Path (Get-Location) '.scheduler/trials/worklist-02/app'
$evidencePath = Join-Path (Get-Location) '.scheduler/trials/worklist-02/evidence/initial/tests'
New-Item -ItemType Directory -Force -Path $evidencePath | Out-Null
node --version | Set-Content (Join-Path $evidencePath 'node-version.txt') -Encoding utf8
Get-Date -Format o | Set-Content (Join-Path $evidencePath 'started-at.txt') -Encoding utf8
Push-Location $appRoot
try {
  node --test 1> (Join-Path $evidencePath 'stdout.txt') 2> (Join-Path $evidencePath 'stderr.txt')
  $commandExitCode = $LASTEXITCODE
  $commandExitCode | Set-Content (Join-Path $evidencePath 'exit-code.txt') -Encoding utf8
} finally { Pop-Location }
Get-Date -Format o | Set-Content (Join-Path $evidencePath 'ended-at.txt') -Encoding utf8
```

不要覆盖已保存的同阶段命令证据；有明确原因的补跑另建attempt-2目录并说明原因。模型用量只记录、不设预算门槛。unknown不自动重发；同一操作无新信息或状态变化时停止重复并报告阻断。防循环不等于少请求就算通过。
